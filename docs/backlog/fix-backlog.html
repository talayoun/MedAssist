M1 — Logout doesn't revoke the staff session Done

Branch fix/logout-session-revocation → merged --no-ff into feat/final-figma-redesign (b6d3701)

  1. Fix applied. logout() now calls addToRevocationSet (the correctly-prefixed function) instead of writing to the wrong Redis key. Dead duplicate verifyToken removed.
  2. Code review dispatched (/superpowers:requesting-code-review). Verdict: production fix correct, verified live — but the regression test was a false negative. Playwright's client auto-clears its cookie on logout's Set-Cookie response, so the "same cookie after logout" check never actually replayed the revoked token.
  3. Test rewritten to replay the raw token explicitly (the real threat model: a stolen/cached cookie). Verified in both directions by swapping in the pre-fix file contents — fails pre-fix (200), passes post-fix (401).
  4. Second bug found while verifying, unrelated to the code review: running the new test alongside others caused 3 unrelated failures. Root cause — staff JWTs had no unique-per-login ID, so two logins to the same account in the same second produced the identical token string; logging out of one silently revoked the other. Invisible before this fix (logout didn't revoke anything for real), a live cross-session bug now that it does.
  5. Scope decision (asked user): folded into M1. Added jti: randomUUID() to the JWT payload so every login's token is unique regardless of timing.
  6. Verified: full tests/api suite — 63/63 passing — after the jti fix.
  7. Shipped. Committed (28b4092), merged, pushed. Worktree removed.
